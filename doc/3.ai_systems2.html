01 / Historical Context

AI Evolution:
From Explicit Rules to Learned Intelligence

จุดเปลี่ยนสำคัญของ AI ไม่ได้เกิดจากโมเดลเพียงอย่างเดียว แต่คือการเปลี่ยน abstraction ที่วิศวกรใช้สร้างระบบ: จากกฎที่มนุษย์กำหนด ไปสู่โมเดลทั่วไปที่เรียนรู้จากข้อมูลและต่อยอดสู่หลายงานได้

1956–1990s

Symbolic AI

Expert systems, logic และ inference engine ที่ขับเคลื่อนด้วยกฎ IF–THEN และฐานความรู้ที่มนุษย์สร้างขึ้น

MYCIN DENDRAL XCON
1990s–2011

Statistical ML

Feature engineering, supervised learning และการใช้ข้อมูลพฤติกรรมเพื่อสร้างโมเดลคาดการณ์และจัดประเภทข้อมูล

Gmail Spam Filter Netflix Recommender Google Translate
2012–2016

Deep Learning

GPU acceleration และ end-to-end representation learning สำหรับงานภาพ เสียง ภาษา และการตัดสินใจที่ซับซ้อน

AlexNet AlphaGo Siri / Alexa ASR
2017–2022

Foundation Models

Transformer, pre-training และโมเดลขนาดใหญ่ที่ปรับใช้ต่อกับงานภาษา การเขียนโค้ด และการค้นหาความรู้ได้

BERT GPT-3 GitHub Copilot
CORE SHIFT — Rules → Features → Representations → General-purpose Models

Speaker Notes / Slide 1

~ 45–60 วินาที

เปิดเรื่อง: “ถ้ามองวิวัฒนาการของ AI ในมุมวิศวกรรม เราไม่ได้เปลี่ยนเพียง algorithm แต่เราเปลี่ยนวิธีออกแบบระบบทั้งหมด”

ยุคแรกคือการเขียนกฎแบบชัดเจน เช่น MYCIN หรือ XCON ซึ่งตรวจสอบ logic ได้ง่าย แต่ขยายผลยากเมื่อเงื่อนไขมีจำนวนมากขึ้น

จากนั้น Machine Learning เปลี่ยนให้ระบบเรียนรู้จากข้อมูล ต่อด้วย Deep Learning และ Transformer ที่ทำให้เกิด foundation model ซึ่งนำไปต่อยอดได้หลายงาน

ส่งต่อ: “วันนี้ AI จึงไม่ใช่แค่โมเดลที่ทำนายผล แต่เริ่มเป็นองค์ประกอบของ workflow ที่ลงมือทำงานร่วมกับระบบองค์กรได้”

02 / Current State

AI in 2026:
From Conversation to Executable Workflows

AI ปัจจุบันไม่ได้มีบทบาทเพียงตอบคำถาม แต่เริ่มเป็นส่วนหนึ่งของระบบงานจริง ที่รับข้อมูลหลายรูปแบบ ใช้เหตุผล เชื่อมต่อเครื่องมือ เรียก API และทำงานภายใต้สิทธิ์ที่กำหนด

Input Layer

OCR Pipeline Computer Vision IoT Telemetry

RBAC Audit Logs Human Approval

Capabilities that matter

  • Multimodal: เข้าใจข้อมูลข้อความ ภาพ เสียง วิดีโอ และข้อมูลจากอุปกรณ์
  • Reasoning & Coding: วิเคราะห์งานหลายขั้น สร้างโค้ด ตรวจสอบโค้ด และจัดทำ technical documentation
  • Agentic Workflow: วางแผน เรียกใช้เครื่องมือ และส่งต่องานตามเงื่อนไขที่กำหนด
  • RAG Integration: เชื่อม knowledge base ภายในเพื่อสร้างคำตอบที่มีบริบทขององค์กร

Engineering requirements

Dimension Design Requirement
Quality Evaluation set, benchmark และ regression test
Reliability Trace, retry, fallback และ observability
Security Permission boundary, data policy และ approval gate
Cost Model routing, caching และ compute/token budget
AI VALUE = MODEL CAPABILITY × RELIABLE SYSTEM INTEGRATION

Speaker Notes / Slide 2

~ 50–65 วินาที

ใจความสำคัญ: “คุณค่าของ AI ไม่ได้มาจากการเลือกโมเดลที่ฉลาดที่สุดเพียงอย่างเดียว แต่มาจากการออกแบบระบบที่ใช้งานได้จริง”

ระบบ AI ที่พร้อมใช้งานต้องมี 4 ชั้น: รับข้อมูล, ประมวลผลด้วยโมเดล, ลงมือทำผ่าน API หรือเครื่องมือ, และชั้นควบคุมความเสี่ยง

ตัวอย่างเช่น AI ช่วยวิเคราะห์ ticket ของฝ่าย IT ได้ แต่ก่อนปิด ticket หรือแก้ไขระบบจริง ต้องกำหนดสิทธิ์ มี log ตรวจสอบ และส่งต่อให้คนอนุมัติเมื่อความเสี่ยงสูง

ส่งต่อ: “เมื่อ AI เริ่มทำงานเป็น agent มากขึ้น คำถามต่อไปจึงไม่ใช่ทำได้หรือไม่ แต่คือควบคุมและเชื่อถือได้มากแค่ไหน”

03 / AGI Era & Near-Term Forecast

September 2027:
AGI-Era Capability → Trusted Autonomous Systems

สมมติฐานของสไลด์นี้คือความสามารถระดับ AGI เกิดขึ้นแล้ว: ระบบสามารถใช้เหตุผลและทำงานข้ามโดเมนได้ในระดับสูง ความท้าทายทางวิศวกรรมจึงเปลี่ยนจาก “ทำให้ AI ฉลาดขึ้น” ไปสู่ “ทำให้ AI ทำงานได้อย่างปลอดภัย เชื่อถือได้ ตรวจสอบได้ และหยุดได้”

AGI-ERA ASSUMPTION — CAPABILITY ≠ PRODUCTION TRUST
00

AGI-Era Systems

  • ทำงานข้ามโดเมน เช่น วิเคราะห์ requirement, เขียนโค้ด, ทดสอบ และสรุปผล
  • วางแผนงานระยะยาว พร้อมปรับแผนเมื่อเงื่อนไขหรือข้อมูลเปลี่ยน
  • แยก “ความสามารถของโมเดล” ออกจาก “สิทธิ์ในการลงมือทำจริง”
Cross-domain Engineer Research Agent Long-horizon Planner
01

Reliable AI Agents

  • วัดผลด้วย task completion rate, error rate และ cost per task
  • Agent ทำงานภายใต้ scope, budget และ permission ที่กำหนด
  • มี retry, fallback, escalation และ human approval
IT Helpdesk Agent Code Review Agent Procurement Agent
02

Hybrid Cloud + Edge

  • Cloud สำหรับ reasoning, simulation และงานที่ใช้ compute สูง
  • Edge model สำหรับ latency ต่ำ ข้อมูลอ่อนไหว หรืออุปกรณ์หน้างาน
  • เลือก routing ตาม cost, performance และ data residency
Factory Vision AI Vehicle AI Offline Assistant
03

Digital Twin Operations

  • เชื่อม AI กับ sensor, vision, historian และ simulation model
  • ใช้เพื่อ predictive maintenance และ quality inspection
  • คำสั่งสู่ระบบจริงต้องผ่าน safety interlock
Digital Twin Predictive Maintenance Smart Factory
04

Governance by Design

  • Policy-as-code, role-based access และ tool permission
  • เก็บ audit trail ของ prompt, context และ tool call
  • ทำ continuous evaluation แบบ DevOps/SRE
Model Monitoring Prompt Evaluation AI Audit Trail
Engineering principle: แม้ระบบจะมีความสามารถระดับ AGI การดำเนินการที่กระทบความปลอดภัย การเงิน คุณภาพการผลิต หรือโครงสร้างพื้นฐาน ต้องมี policy boundary, human override, rollback และ auditability เสมอ
2026 → 2027

AGI-era assumption: AI สามารถใช้เหตุผลและทำงานข้ามโดเมนได้มากขึ้น
Engineering requirement: Reliable + Observable + Governed + Human-Controllable

Speaker Notes / Slide 3

~ 60–75 วินาที

เกริ่น: “ในสไลด์นี้ เราตั้งสมมติฐานเชิงกลยุทธ์ว่า AI มีความสามารถทำงานข้ามโดเมนระดับสูง หรือเข้าสู่ยุค AGI แล้ว”

แต่ความสามารถของโมเดลไม่เท่ากับความพร้อมในการใช้งานใน production โดยเฉพาะในโรงงาน ระบบการเงิน หรือระบบที่กระทบความปลอดภัย

ดังนั้นระบบต้องมีขอบเขตสิทธิ์ มีงบประมาณและเวลาสำหรับ agent มีการตรวจสอบทุก tool call และมีมนุษย์เข้ามาอนุมัติหรือหยุดระบบได้เสมอ

ส่งต่อ: “เมื่อเข้าใจหลักการควบคุมแล้ว ขั้นต่อไปคือเลือกโมเดลให้เหมาะกับประเภทงาน ไม่ใช่ใช้โมเดลเดียวกับทุก use case”

~ 60–75 วินาที

เกริ่น: “สไลด์สุดท้ายเป็นมุมมองการเลือกโมเดลตามประเภทงาน แทนที่จะถามว่าโมเดลไหนดีที่สุดโดยรวม”

งาน social media ควรเน้นความคิดสร้างสรรค์และ multimodal ขณะที่งานบริหารควรเน้นการสรุปเอกสาร การเชื่อม knowledge base และการกำกับสิทธิ์ข้อมูล

บทสรุป: “เริ่มจาก workflow และระดับความเสี่ยง เลือกโมเดล ทดสอบกับชุดงานจริง แล้วจึงออกแบบ governance และ integration ให้ครบวงจร”
